🐧 Linux

📌 What is Linux?

Linux is an open-source operating system that manages hardware and software resources on a computer.

  • It acts as a bridge between hardware and applications
  • Used in servers, cloud platforms, and DevOps environments
  • Known for being stable, secure, and customizable
💡 Most servers on the internet run Linux!
02
🐧 Linux — Files & Directory Structure

📁 Files in Linux

In Linux, everything is treated as a file:

  • Text files
  • Directories (folders)
  • Devices (like disks)

📂 Directory Structure

Linux uses a hierarchical file system:

/
├── home/  ← User directories
├── etc/   ← Configuration files
├── var/   ← Variable data (logs, etc.)
└── bin/   ← Essential commands

Important Directories:

  • /home → User files
  • /etc → Configuration files
  • /var → Logs and variable data
  • /bin → Essential commands

🐧 Linux — Users & Groups

👤 Users and Groups in Linux

Linux is a multi-user system, meaning multiple users can use it safely.

Users:

  • Each user has a username and home directory
  • Example: /home/tim

Groups:

  • Users can belong to groups
  • Used to manage permissions efficiently

Why it matters:

  • Controls access to files and systems
  • Important for security in DevOps
05
🐧 Linux — File Permissions & chmod

🔐 File Permissions and chmod

Every file in Linux has permissions:

-rwxr-xr--

Breakdown:

  • r → read
  • w → write
  • x → execute

Permission Groups:

  • Owner
  • Group
  • Others

🔧 Changing Permissions with chmod:

chmod 755 file.sh
  • Owner → full access
  • Group → read & execute
  • Others → read & execute

💡 Why Permissions Matter:

  • Protect sensitive data
  • Control who can run scripts
  • Essential for secure DevOps pipelines

🌐 Network Basics

📌 What is a Network?

A network is a group of computers and devices connected together to share data and resources.

  • Allows communication between systems
  • Can be wired (cables) or wireless (Wi-Fi)
  • Essential for internet, cloud, and DevOps systems
💡 Every DevOps system relies on networks to function!

🧭 IP Address

An IP Address is a unique identifier for a device on a network — like a home address, but for computers.

192.168.1.1

Types of IP:

  • Public IP → Used on the internet
  • Private IP → Used inside local networks
💡 Without IP addresses, devices cannot communicate!
08
🌐 Network Basics — LAN & WAN

🏠 LAN (Local Area Network)

A LAN is a network that connects devices in a small area.

Examples:

  • Home network
  • School or office network

Characteristics:

  • High speed
  • Limited geographic area
  • Usually privately owned
💡 Your Wi-Fi at home is a LAN!

🌍 WAN (Wide Area Network)

A WAN connects networks over a large geographic area.

Example:

  • The Internet (largest WAN)

Characteristics:

  • Covers cities, countries, or continents
  • Slower than LAN (generally)
  • Connects multiple LANs together
💡 DevOps systems often run across WANs (cloud infrastructure)
09
🌐 Network Basics — HTTP & HTTPS

🌐 HTTP (HyperText Transfer Protocol)

HTTP is a protocol used to transfer data between a web browser and a server.

  • Used when you visit websites
  • Works on port 80
  • Data is sent in plain text
http://example.com
⚠️ Not secure — data can be intercepted by anyone on the network

🔒 HTTPS (HyperText Transfer Protocol Secure)

HTTPS is the secure version of HTTP.

  • Protects sensitive information (passwords, payments)
  • Works on port 443
  • Encrypts data in transit using TLS/SSL
https://example.com
💡 Always prefer HTTPS in real applications!
10
🌐 Network Basics — TCP & UDP

📦 TCP (Transmission Control Protocol)

TCP ensures reliable data delivery.

Features:

  • Data is sent in order
  • Errors are checked and corrected
  • Guarantees delivery

Use Cases:

  • Web browsing
  • File transfers
💡 Think of TCP like a tracked delivery service

⚡ UDP (User Datagram Protocol)

UDP sends data faster but without guarantees.

Features:

  • No error checking
  • No delivery confirmation
  • Faster than TCP

Use Cases:

  • Video streaming
  • Online gaming
💡 Think of UDP like regular mail (fast but no tracking)

🔄 TCP vs UDP

FeatureTCPUDP
SpeedSlowerFaster
ReliabilityHighLow
Error CheckingYesNo
Use CasesWebsites, APIsStreaming, gaming
11
🌐 Network Basics — Summary

🚀 Summary

🔗Networks connect devices for communication
🏷️IP addresses identify devices on a network
🏠LAN = small networks, WAN = large networks
🔒HTTP/HTTPS handle web communication
📦TCP = reliable, UDP = fast

🎯 Key Takeaway

👉 Networking is the foundation of DevOps, because all systems, services, and tools communicate over networks

🔧 Git & GitHub

📌 What is Version Control?

Version Control is a system that helps track changes in files over time.

  • Keeps history of changes
  • Allows reverting to previous versions
  • Enables collaboration between multiple developers
💡 Think of it like "track changes" but for code projects

🧰 What is Git?

Git is a distributed version control system.

  • Tracks changes in code
  • Works locally on your computer
  • Fast and efficient
  • Widely used in DevOps and software development

Key Idea:

Every developer has a full copy of the project history

💡 Git is the core tool for managing code in DevOps

⚙️ Jenkins

📌 What is Jenkins?

Jenkins is an automation server used in DevOps to automate tasks like:

  • Building code
  • Testing applications
  • Deploying software
💡 It helps developers deliver software faster and more reliably

🤔 Why Jenkins is Used in DevOps

  • Automates repetitive tasks
  • Reduces human errors
  • Integrates with many tools (Git, Docker, etc.)

👉 Key Idea: Automation = Speed + Consistency

19
⚙️ Jenkins — Architecture

🏗️ Jenkins Architecture

Jenkins uses a Controller–Agent model to manage and distribute work:

🖥️ Controller (Master)
Manages jobs, schedules tasks, monitors agents
⚙️ Agent (Worker)
Executes the actual build & test tasks
💡 This allows Jenkins to scale and run multiple jobs at once across many machines

Flow:

Controller  →  assigns job  →  Agent
Agent       →  runs tasks  →  reports back to Controller
20
⚙️ Jenkins — In Action

🔧 Jenkins in Action

Basic CI/CD flow triggered by Jenkins:

  1. Developer pushes code to GitHub
  2. Jenkins detects the change automatically
  3. Jenkins runs build & tests
  4. Jenkins deploys the application

Pipeline Flow:

GitHub Push  →  Jenkins detects  →  Build  →  Test  →  Deploy
💡 This is the heart of CI/CD — automated from commit to deployment

🔄 CI/CD

📌 What is CI/CD?

CI/CD is a method to automatically build, test, and deploy code.

  • CI → Continuous Integration
  • CD → Continuous Delivery / Deployment

🔁 Continuous Integration (CI)

Developers push code frequently and the code is automatically processed:

🛠️Built
Code is compiled & packaged
🧪Tested
Automated tests run on every push
💡 Goal: Catch bugs early before they reach production
23
🔄 CI/CD — Delivery vs Deployment

🚀 Continuous Delivery vs Deployment

📦 Continuous Delivery
  • Code is ready to deploy at any time
  • Requires manual approval before going live
🤖 Continuous Deployment
  • Code is deployed automatically
  • No manual step needed
  • Fully automated end-to-end

👉 Deployment = Fully automated — code goes live without any human intervention

🌟 Benefits of CI/CD

  • Faster development cycles
  • Fewer bugs reaching production
  • Quick, reliable releases
  • Better collaboration across teams
24
🔄 CI/CD — Workflow & Summary

🔄 CI/CD Workflow

Code  →  Build  →  Test  →  Deploy
  1. Code — Developer pushes changes to the repo
  2. Build — Code is compiled and packaged automatically
  3. Test — Automated tests validate the build
  4. Deploy — Passing builds go to staging or production

🚀 Summary

🔁CI automatically builds & tests on every push
📦CD ensures code is always ready to ship
🤖Deployment makes releases fully automated
⚡Result: faster, safer, more reliable software delivery

🎯 Key Takeaway

👉 CI/CD eliminates manual bottlenecks — every commit automatically moves toward production

🐳 Docker

Docker is a platform that allows you to build, run, and ship applications in containers.

  • Packages app + dependencies together
  • Runs the same everywhere (dev, test, production)
  • Lightweight and fast
💡 "It works on my machine" problem → solved with Docker
30
🐳 Docker — Containers vs VMs

⚖️ Containers vs Virtual Machines

📦 Containers:
  • Share the host OS
  • Lightweight and fast
  • Start in seconds
🖥️ Virtual Machines:
  • Have their own OS
  • Heavier and slower
  • Take more resources
💡 Containers are more efficient for DevOps workflows

☸️ Kubernetes

📌 What is Kubernetes?

Kubernetes is an open-source container orchestration platform used to manage and automate containerized applications.

It helps with:

  • Deploying containers
  • Scaling applications
  • Managing container health
💡 Kubernetes is often called K8s

❓ Why Kubernetes is Needed

Managing a few containers with Docker is easy, but managing hundreds is difficult. Kubernetes helps by:

  • Automatically restarting failed containers
  • Scaling applications up or down
  • Distributing traffic between containers
35
☸️ Kubernetes — Architecture

🏗 Kubernetes Architecture

Kubernetes works using Master Node and Worker Nodes

Master Node

Controls the cluster:

  • API Server
  • Scheduler
  • Controller Manager

Worker Node

Runs the application containers inside Pods

36
☸️ Kubernetes — Core Components

📦 Pods, Services, Deployments

🐳 Pod
The smallest unit in Kubernetes. Runs one or more containers.
🌐 Service
Provides a stable way to access Pods. Balances traffic between them.
📜 Deployment
Manages Pod replicas and updates. Keeps the desired number running.

  • Reduce Pods when traffic decreases

🤖 Ansible

📌 What is Ansible?

Ansible is an automation tool used to manage and configure servers.

  • Open-source
  • Simple and easy to use
  • Works over SSH
💡 Used in DevOps to automate repetitive tasks

🧠 Configuration Management

Keeping systems consistent and correctly configured:

  • Installing software
  • Updating servers
  • Managing settings
💡 Instead of doing tasks manually, Ansible automates them
41
🤖 Ansible — Agentless & Architecture

🤖 Agent vs Agentless

🛡️ Agent-Based:
Requires software installed on each server.
🚀 Agentless (Ansible):
No software needed on target machines. Uses SSH to connect.

✅ Ansible is agentless, making it simple and lightweight

🏗️ Ansible Architecture

Ansible has a simple structure:

  • Control Node → where Ansible runs
  • Managed Nodes → servers being controlled
Control Node ---> Managed Nodes
💡 One control node can manage many servers
42
🤖 Ansible — Playbooks & YAML

📜 Playbooks and YAML

Ansible uses Playbooks to define tasks.

  • Written in YAML (easy to read)
  • Describe what actions to perform

Example Playbook:

- name: Install nginx
  hosts: web
  tasks:
    - name: Install package
      apt:
        name: nginx
        state: present
43
🤖 Ansible — Inventory & Summary

🗂️ Inventory

An inventory file tells Ansible which servers to manage.

  • Groups servers together
  • Used by playbooks

Example inventory.ini:

[web]
192.168.1.10
192.168.1.11

🚀 Summary

⚙️Automates configuration management
🚀Agentless architecture (uses SSH)
📜Uses simple YAML Playbooks
🗂️Manages servers via Inventory

🏗️ IaC

📌 What is Infrastructure as Code (IaC)?

Infrastructure as Code (IaC) is the practice of managing infrastructure using code instead of manual setup.

  • Servers, networks, and databases are defined in files
  • Changes can be version-controlled (like Git)
  • Makes infrastructure repeatable and consistent
💡 Instead of clicking in a UI → you write code

⚡ Why IaC is Important

🚀Faster setup (automation)
🔁Consistency (no human errors)
📜Version control (track changes)
🧪Easy testing and rollback

💡 Essential for modern DevOps workflows

48
🏗️ IaC — Declarative vs Imperative

🔄 Declarative vs Imperative

🎯 Declarative:
  • You define what you want
  • Tool decides how to create it
Example: "Create a server with 2 CPUs"
🛠️ Imperative:
  • You define how to do it step by step
Example: "Log in, install dependencies, run command A, then command B..."
💡 Terraform uses declarative approach
